Assunto: Hotfix Essentia (mobile) – 4 correções diretas + rebuild

Fala! No mobile ainda está igual ao build anterior. Seguem correções objetivas com trechos de código para colar:

1) “Harmonizar” não abre o vídeo (bug real)

Hoje o FEMECompassLive ignora o onHarmonize recebido do pai. Resultado: recalcula coerência, mas não navega para a tela de respiração/vídeo.

Patch (client/src/pages/purpose.tsx)

ANTES

<FEMECompass 
  values={femeState}
  coherence={coherence}
  onHarmonize={isCalculating ? undefined : handleCalculateCoherence}
/>


DEPOIS

<FEMECompass 
  values={femeState}
  coherence={coherence}
  onChange={async (next) => {
    const { actions } = await import('@/state/integration-engine');
    await actions.updateFeme(next); // salva mudanças do FEME
  }}
  onHarmonize={isCalculating ? undefined : handleCalculateCoherence}
/>


E dentro de handleCalculateCoherence chame o callback para navegar:

const handleCalculateCoherence = async () => {
  setIsCalculating(true);
  try {
    const { actions } = await import('@/state/integration-engine');
    await actions.recalcCoherence();
    onHarmonize?.(); // <—— aciona navegação (ex.: /breathing-446)
  } catch (e) {
    console.error('[FEME] Erro ao calcular coerência:', e);
  } finally {
    setIsCalculating(false);
  }
};


Efeito: ao tocar “Harmonizar”, recalcula e abre o vídeo como esperado.

2) Alterar FEME não muda nada

O componente não estava persistindo as mudanças. O patch do item 1 já adiciona onChange chamando actions.updateFeme(next).
Se o FEMECompass expõe outro nome de prop (ex.: onValuesChange), ajuste para ele.

3) Menu de abas não fica sticky e ocupa muito

O position: sticky quebra se algum ancestral tem transform ou overflow diferente. Simplifica o sticky no mobile e evita ancestrais com transform/overflow que quebrem isso.

Patch (CSS global – client/src/index.css)
/* STICKY MENU – garante que nada acima “quebre” o sticky */
.page, .page * {
  /* não force transform nos containers acima do sticky */
  transform: none !important;
}

.sticky-menu {
  position: sticky;
  top: calc(var(--compass-h, 80px) + 8px);
  z-index: 40;
}

/* Botões mais compactos no mobile */
@media (max-width: 420px) {
  .sticky-menu .sticky-menu-inner button {
    padding-left: .25rem;
    padding-right: .25rem;
    height: 44px;       /* não passa do “safe” */
    font-size: 12px;
  }
}

Patch (JSX – onde está o sticky do mobile, em purpose.tsx)

ANTES

<div className="lg:hidden sticky-menu no-transform mt-2">


DEPOIS

<div className="lg:hidden sticky-menu mt-2">


Removemos no-transform e deixamos o CSS acima garantir o sticky.
O --compass-h já está sendo setado via useLayoutEffect; mantenha.
